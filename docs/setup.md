# Setup Guide

This guide reproduces the 6-channel ESP32 relay controller. Where the source code does not specify something, it is marked **Not specified in the source code**.

## 1. Hardware requirements

- 1 × ESP32 development board (DevKit / WROOM-style)
- 1 × 6-channel relay module (active-LOW inputs, or set `RELAY_ACTIVE_LOW false`)
- 6 × physical switches (momentary or maintained)
- Power supply for the ESP32 and relay module (**Not specified in the source code**)
- Appliances and their wiring (**Not specified in the source code**)
- USB cable for programming

Pin details: [wiring.md](wiring.md). Full list: [components.md](../hardware/components.md).

## 2. Software requirements

- Arduino IDE 2.x (or the Arduino Cloud web editor)
- A free Arduino account with access to [Arduino Cloud](https://app.arduino.cc)
- ESP32 board package
- Arduino IoT Cloud library and its dependencies (installed through Library Manager)

## 3. Arduino IDE setup

1. Install Arduino IDE.
2. Sign in to Arduino Cloud in the browser to create your Thing and device (section 6).
3. Open or create a sketch with the firmware, plus the generated `thingProperties.h` and your secrets file (section 6).

## 4. ESP32 board setup

1. **File → Preferences → Additional boards manager URLs**: add `https://espressif.github.io/arduino-esp32/package_esp32_index.json`.
2. **Tools → Board → Boards Manager**: search for "esp32" (by Espressif Systems) and install.
3. **Tools → Board**: select **ESP32 Dev Module** (or the entry matching your board). Your exact model is not specified in the code.
4. Select the correct port under **Tools → Port**.

## 5. Required libraries

Install via **Tools → Manage Libraries**:

- `ArduinoIoTCloud`
- `Arduino_ConnectionHandler` (usually installed automatically with `ArduinoIoTCloud`)

`thingProperties.h` is generated by Arduino Cloud and includes what the sketch needs. Other libraries needed by that file: **Not specified in the source code**.

## 6. Arduino IoT Cloud setup

1. In Arduino Cloud, go to **Devices → Add** and choose **Third-party device → ESP32** (pick the board matching yours).
2. Save the **Device ID** and **Secret Key** that are shown. They are displayed only once. **Never commit them to GitHub.**
3. Go to **Things → Create**, name it, and associate it with your device.
4. In the Thing's **Network** section, enter your Wi-Fi credentials and the Secret Key (section 8).
5. Add the cloud variables (section 7).
6. Open the **Sketch** tab. Arduino Cloud generates `thingProperties.h`. Copy the firmware code into the main sketch, keeping the `#include "thingProperties.h"` line.

## 7. Cloud variables / properties

Create six variables in the Thing. The code uses the type `CloudLight`, so choose **Light** (a Smart Home type).

| Name | Type | Permission | Callback generated |
| ---- | ---- | ---------- | ------------------ |
| `light1` | Light | Read & Write | `onLight1Change()` |
| `light2` | Light | Read & Write | `onLight2Change()` |
| `light3` | Light | Read & Write | `onLight3Change()` |
| `light4` | Light | Read & Write | `onLight4Change()` |
| `light5` | Light | Read & Write | `onLight5Change()` |
| `light6` | Light | Read & Write | `onLight6Change()` |

Names must match the code exactly. Read & Write is the usual setting for controllable variables; the code itself does not state permission or update policy. The variable names `light1`–`light6` (or any friendly name you assign) are what you will say to a voice assistant.

## 8. Wi-Fi configuration

Credentials are entered in the Arduino Cloud **Network** section and live in a secrets file that is not part of the provided code. Use placeholders in anything you publish:

```cpp
// secrets.h  (DO NOT COMMIT REAL VALUES)
#define SECRET_SSID        "WIFI_SSID"
#define SECRET_OPTIONAL_PASS "WIFI_PASSWORD"
// Device ID and secret key are managed by Arduino Cloud:
//   DEVICE_ID  = "DEVICE_ID"
//   SECRET_KEY = "SECRET_KEY"
```

Add the secrets file to `.gitignore`. The exact macro names depend on what Arduino Cloud generates for your Thing.

## 9. Wiring

Follow [wiring.md](wiring.md) and the diagrams in `circuit/`. In summary:

- Relay IN1–IN6 ← GPIO 23, 22, 21, 19, 18, 5.
- Switches 1–6 between GPIO 32, 33, 25, 26, 27, 14 and GND.
- ESP32 GND, relay GND and switch GND share a common ground.

Test the control side with **no appliances connected** first.

## 10. Uploading firmware

1. Connect the ESP32 over USB and select the board and port.
2. Click **Upload**. If the upload hangs, hold the BOOT button on the board until it begins.
3. Open **Tools → Serial Monitor** at **115200 baud**.

## 11. Testing

1. Serial Monitor shows `[BOOT] 6-Channel Smart Home Switch Controller`, then `[SYNC] Cloud properties synchronized with relay states.`
2. When connected to the cloud: `[WIFI] Connection (re)established.` and the status LED blinks every 500 ms.
3. In the Arduino Cloud dashboard, add a Switch/Light widget for each variable. Toggle each one; you should see `[RELAY] Channel N -> ON/OFF` and hear the relay click.
4. Press each physical switch: the matching relay toggles and the dashboard widget updates.
5. **Offline test:** turn off your router. The status LED becomes solid. Physical switches should still toggle the relays. Turn the router back on: the log shows `[WIFI] Connection (re)established.` and the dashboard catches up.

Remember: all relays start OFF after any power cycle.

## 12. Google Assistant setup

Voice control is not implemented in the firmware. It comes from the Arduino Cloud integration with your Light-type variables. Menu names may change; check the [Arduino Cloud documentation](https://docs.arduino.cc/arduino-cloud/) if something differs.

1. Open the **Google Home** app.
2. **+ → Set up device → Works with Google**.
3. Search for **Arduino** (Arduino IoT Cloud) and sign in with your Arduino account.
4. Your Light variables should appear as lights. Assign them to a room and name them.
5. Test: "Hey Google, turn on *name*."

## 13. Alexa setup

1. Open the **Alexa** app.
2. **More → Skills & Games**, search for **Arduino**, then **Enable to use** and link your Arduino account.
3. Run **Discover devices** (or say "Alexa, discover devices").
4. Test: "Alexa, turn on *name*."

## 14. Troubleshooting

| Problem | Things to check |
| ------- | --------------- |
| Relay is ON when it should be OFF (inverted) | Your module is active-HIGH. Set `RELAY_ACTIVE_LOW false`. |
| Relay does not click | Common GND between ESP32 and relay module; relay VCC per module datasheet; correct IN pin. |
| Switch toggles twice or bounces | Increase `DEBOUNCE_DELAY` (40 ms default); check wiring. |
| Relay clicks briefly at power-up | GPIO 5 is a boot-strapping pin. See the caveats in [wiring.md](wiring.md). |
| Upload fails or boot loop | Disconnect anything pulling GPIO 2/5 at boot; try holding BOOT. |
| LED is solid, device offline in the cloud | Check Wi-Fi credentials, 2.4 GHz network, Device ID and Secret Key. |
| Dashboard value is stale | Wait for reconnect; the firmware pushes real states on reconnect. |
| Compile error about `thingProperties.h` | Use the file generated by your Thing; make sure it is in the sketch folder. |
| Alexa / Google cannot find devices | Variables must be of type **Light**; re-link the account; re-discover. |
| Cloud change made while the ESP32 was offline | What happens on reconnect is decided by Arduino Cloud's sync; **Not specified in the source code**. The firmware pushes its own relay states after reconnect. |

## 15. Safety notes

- **AC mains can kill.** If your relays switch mains, have a qualified electrician do the load wiring.
- Disconnect power before changing any wiring.
- Use properly rated relays, wires, fuses and an insulated enclosure. Ratings are **not specified in the source code**.
- Keep low-voltage and mains wiring physically separated.
- Test the control side without any load first.
- Never commit Wi-Fi passwords, Device ID, Secret Key or tokens to a public repository.
